# Part 1 — Core Python Concepts

## 1. Variable

A **variable** is a name that refers to a stored value.

```python
student_name = "Kong Sattha"
student_year = 4
score = 85
```

- `student_name` holds text (a string).
- `student_year` holds a whole number (an integer).
- `score` holds a number.

Once a value is stored, it can be reused anywhere later in the program:

```python
print(student_name)
print(score)
```

> **Key idea:** a variable stores a value under a name.

---

## 2. Function

A **function** is a reusable block of code that performs one specific task.

```python
def calculate_sum(a, b):
    return a + b


result = calculate_sum(5, 3)
print(result)
```

Output:

```text
8
```

Rather than repeating the same calculation in several places, I write it once and call the function whenever it is needed.

> **Key idea:** a function packages a task so it can be reused.

---

## 3. Class

A **class** is a blueprint that describes what an object looks like and what it can do.

```python
class Student:
    pass
```

`Student` defines a type of object. To create an actual object from it, I call the class:

```python
student1 = Student()
```

`student1` is an **object** (also called an *instance*) of the `Student` class.

> **Key idea:** a class is the blueprint, and an object is something built from it.

---

## 4. Method

A **method** is a function that is defined inside a class and works on the objects of that class.

```python
class Student:
    def __init__(self, name):
        self.name = name

    def study(self):
        print(f"{self.name} is studying.")


student1 = Student("Kong Sattha")
student1.study()
```

Output:

```text
Kong Sattha is studying.
```

Here:

- `__init__` is a special method that runs when a new object is created. It stores the student's name.
- `self` refers to the object that is calling the method.
- `study()` is a method because it is defined inside the `Student` class.

> **Key idea:** a method is a function that belongs to a class.

---

## 5. Constant

A **constant** is a value that is meant to stay the same while the program runs.

```python
PI = 3.14159
MAX_SCORE = 100
```

Python does not actually stop me from changing these values. By convention, programmers write constant names in uppercase to signal that they should not be modified.

> **Key idea:** a constant is a value that should stay fixed.

---

## 6. Module

A **module** is a single Python file that contains reusable code.

Suppose I have a file named `calculator.py`:

```python
def add(a, b):
    return a + b
```

Another file can import and use it:

```python
import calculator

print(calculator.add(5, 2))
```

> **Key idea:** a module is one Python file with reusable code.

---

## 7. Package

A **package** is a directory that groups related modules together.

```text
data_tools/
│
├── __init__.py
├── cleaning.py
├── analysis.py
└── visualization.py
```

In this layout:

- `data_tools` is the package.
- `cleaning.py`, `analysis.py`, and `visualization.py` are modules.
- `__init__.py` marks the folder as a regular package, and it can also hold package-level setup code.

> **Key idea:** a package is a collection of related modules.

---

## Summary of the Basic Concepts

| Concept | Meaning |
|---|---|
| Variable | Stores a value |
| Function | Performs a reusable task |
| Class | Blueprint used to create objects |
| Object | An instance created from a class |
| Method | A function defined inside a class |
| Constant | A value intended not to change |
| Module | A Python file containing reusable code |
| Package | A folder of related modules |

## How the Concepts Fit Together

Code is organized in layers, from the largest container to the smallest:

```text
Package
   ↓
Module
   ↓
Class
   ↓
Method
```

Variables, functions, and constants can appear at any level:

```text
Variable → stores information
Function → performs an action
Constant → stores a value that should stay fixed
```

# Part 2 — Clean Code and Best Practices

Code that merely works is not enough. Good code should also be easy for other people (and for my future self) to read, change, test, and maintain.

## 1. Readability

**Readability** means the code is easy to understand at a glance.

Hard to read:

```python
a = 10
b = 3
c = a * b
```

Easier to read:

```python
price = 10
quantity = 3
total_price = price * quantity
```

Both versions give the same result, but only the second one tells the reader what each value means.

> **Remember:** readable code is easy to understand.

---

## 2. Maintainability

**Maintainability** means the code is easy to change or improve later.

Repeating the same logic invites mistakes:

```python
total1 = 10 * 2
total2 = 20 * 3
total3 = 15 * 4
```

Moving it into a function keeps it in one place:

```python
def calculate_total(price, quantity):
    return price * quantity


total1 = calculate_total(10, 2)
total2 = calculate_total(20, 3)
total3 = calculate_total(15, 4)
```

If the calculation ever changes, I only have to edit the function.

> **Remember:** maintainable code is easy to update.

---

## 3. Efficiency

**Efficiency** means solving a problem with a suitable, simple solution that uses time and resources sensibly.

```python
numbers = [10, 20, 30, 40]
```

Instead of adding the numbers with a manual loop:

```python
total = 0

for number in numbers:
    total = total + number
```

I can use Python's built-in `sum()`:

```python
total = sum(numbers)
```

The built-in version is shorter, clearer, and usually faster.

> **Remember:** prefer simple, appropriate solutions, and use built-in tools when they exist.

---

## 4. Reducing Errors

A good program anticipates problems and handles them safely.

```python
try:
    age = int(input("Enter your age: "))
    print(age)

except ValueError:
    print("Please enter a number.")
```

If the user types something like `hello`, the program does not crash. It shows a helpful message instead. Catching a specific exception such as `ValueError` is better than catching everything, because it avoids hiding unrelated bugs.

> **Remember:** error handling lets a program cope with unexpected input.

---

## Why Best Practices Matter

| Principle | Meaning | Example |
|---|---|---|
| Readability | Easy to understand | Use meaningful variable names |
| Maintainability | Easy to update | Put repeated logic in functions |
| Efficiency | A suitable, simple solution | Use built-in functions |
| Error handling | Problems are managed safely | Use `try`/`except` |

# Part 3 — PEP 8 Coding Style

## What is PEP 8?

**PEP 8** is the official style guide for Python code. It gives recommendations so that Python code looks consistent from one programmer to another.

```text
Clean code
   ↓
Consistent code
   ↓
Readable code
   ↓
Easier collaboration
```

---

## 1. Use Meaningful Names

Names should describe what they hold or do.

Avoid:

```python
x = 50
y = 4
z = x * y
```

Prefer:

```python
product_price = 50
quantity = 4
total_price = product_price * quantity
```

Good names reduce the need for extra explanation.

---

## 2. Variables and Functions Use `snake_case`

Names are written in lowercase, with words separated by underscores.

```python
student_name = "Kong Sattha"
final_score = 90


def calculate_average():
    pass
```

> **Remember:** variables and functions → `snake_case`.

---

## 3. Classes Use `PascalCase`

Each word in a class name starts with a capital letter, with no underscores.

```python
class StudentProfile:
    pass


class DataProcessor:
    pass
```

> **Remember:** classes → `PascalCase`.

---

## 4. Constants Use `UPPERCASE`

Constants are written in capital letters, with underscores between words.

```python
PI = 3.14159
MAX_USERS = 100
DEFAULT_TIMEOUT = 30
```

> **Remember:** constants → `UPPERCASE`.

---

## 5. Indent with Four Spaces

Python uses indentation to define blocks of code, and PEP 8 recommends **4 spaces** per level.

Not recommended:

```python
if score >= 50:
  print("Pass")
```

Recommended:

```python
if score >= 50:
    print("Pass")
```

---

## 6. Put Spaces Around Operators

Avoid:

```python
total=price*quantity
```

Prefer:

```python
total = price * quantity
```

---

## 7. Put a Space After Commas

Avoid:

```python
scores = [70,80,90,100]
calculate_total(10,2)
```

Prefer:

```python
scores = [70, 80, 90, 100]
calculate_total(10, 2)
```

---

## 8. Keep Imports Organized

Imports go at the top of the file, one per line. A common order is the standard library first, then third-party packages, then my own modules, each group separated by a blank line.

```python
import math

import numpy as np
import pandas as pd
```

This makes the dependencies of a file easy to see.

---

## 9. Keep Lines Short

PEP 8 suggests limiting lines to about 79 characters. Long statements are hard to read, so I split them up.

Instead of:

```python
result = calculate_final_price(price, quantity, discount, tax, shipping_cost, service_fee)
```

Write:

```python
result = calculate_final_price(
    price,
    quantity,
    discount,
    tax,
    shipping_cost,
    service_fee,
)
```

---

## 10. Use Blank Lines

Blank lines separate the parts of a program. Top-level functions and classes are separated by two blank lines.

```python
def add(a, b):
    return a + b


def subtract(a, b):
    return a - b
```

Without them, longer files quickly become hard to scan.

---

## 11. Write Useful Comments

A comment should add information that the code does not already show.

Unnecessary:

```python
# Add two numbers
result = a + b
```

Better:

```python
# Calculate the student's final score after applying the bonus
final_score = score + bonus
```

> **Remember:** good comments explain *why* something is done, not just *what*.

---

## PEP 8 Quick Reference

| Item | Recommended style |
|---|---|
| Variables | `snake_case` |
| Functions | `snake_case` |
| Classes | `PascalCase` |
| Constants | `UPPERCASE` |
| Indentation | 4 spaces |
| Operators | Spaces around them |
| Commas | A space after each comma |
| Imports | At the top, grouped and organized |
| Line length | About 79 characters; break long lines |
| Top-level definitions | Separated by blank lines |
| Comments | Explain useful or non-obvious logic |

# Basic Debugging Process

When a program fails, I should not rewrite everything straight away. Instead, I follow a steady process:

```text
Run the program
      ↓
Read the error message
      ↓
Find the line that caused it
      ↓
Understand the type of error
      ↓
Check the values involved
      ↓
Fix one problem
      ↓
Run again
```

For example:

```python
quantity_text = "20"

print(quantity_text + 5)
```

This fails with:

```text
TypeError: can only concatenate str (not "int") to str
```

`"20"` is a string and `5` is an integer, and Python does not add the two together. Converting the string first fixes the problem:

```python
quantity_text = "20"

print(int(quantity_text) + 5)
```

Output:

```text
25
```
